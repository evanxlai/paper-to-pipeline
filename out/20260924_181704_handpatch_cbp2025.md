# Hand patch of the cbp2025 port, 2026-09-24 (not produced by the loop)

**Port:** run 20260924_102657, `~/cbp2025_port` on the cbp2025_host worker.
**File:** `cbp2016_tage_sc_l.h`. The original is backed up at
`~/cbp2025_port_handpatch_backup_20260924/cbp2016_tage_sc_l.h` on the same worker.
**Why by hand:** time. The loop fix (gate condition G6, see `loop/gate.py`) went in at the
same time, but the port was not re-integrated under it. So a stage-4 result from this port
says how sR tunes on the port. It says nothing about whether stage 3 can produce a
tunable port unaided.

## What was wrong

The stage-4 preflight refused: all 19 host knobs, plus `SR_ROB_IDX_BITS` and
`SR_INFLIGHT_BRANCHES`, built byte-identical binaries. Verified against the transcripts
and the worker's tree:

- **Turn 0** wired only 5 of the 19 host knobs (`patch_s1.py`). Its table had wrong default
  values for 4 knobs, missed `LOGLNB` on a whitespace difference, and left out 9 knobs
  entirely. Measured by running its substitutions on the pristine file.
- **Turn 3** (the G3 debug turn) ran `git checkout cbp2016_tage_sc_l.h` repeatedly, then
  rebuilt the file with the sR hooks only. The file was last written at 13:49:29, and it has
  no `sr_params.h` include and no `HOST_*`.
- **G1 to G5** cannot see this: at the defaults, a wired port and an unwired one build the
  same binary.

## What was changed

`#include "sr_params.h"` after the last system include, and each of the plan's 19
`host_knobs` rewritten from `#define <host_symbol> <default>` to
`#define <host_symbol> <macro>`. The substitutions were driven by the plan's own
`host_knobs`, and each was required to match exactly once.

## How it was checked

- **G6 on the patched port** (`hosts/cbp2025/adapter.py:knob_reach`, the production path;
  400 s, report in `20260924_181704_handpatch_cbp2025_g6.json`): all 19 host knobs live, builds
  reproducible. It still fails on `SR_ROB_IDX_BITS` and `SR_INFLIGHT_BRANCHES` (see below).
- **Defaults unchanged.** Patched and unpatched file built in the same scratch tree
  (`~/cbp2025_reach`) with the port's own `sr_params.h`:
  - the preprocessed translation unit (40902 lines) differs in one line, an `assert`'s
    `__LINE__` (516 vs 515);
  - `./cbp` output is byte-identical on both sample traces, sR off and sR on.

  Whole-binary digests are not comparable across trees, because the build directory is
  embedded in the debug info.

## Not fixed: two sR knobs the port does not realize

- `SR_ROB_IDX_BITS`: register payloads are stored as `uint32_t`.
- `SR_INFLIGHT_BRANCHES`: in-flight state is a bitset plus a copy of all 65 payloads on
  every checkpointed history, with no bound tied to the macro.

Making either live would mean choosing how to bound in-flight state, which the plan
does not say, so neither was patched. Stage 4 has to pin both (`P2P_DSE_PIN`). Pinned,
they are charged at their defaults and cannot move.

The port's real in-flight storage is larger than the spec's
`inflight_branches * num_logical_regs` bits, so the storage figure understates this port
by that difference.
