### Root Cause
The core issue was a severe C++ One Definition Rule (ODR) violation that completely severed the prediction path from the instruction update path. 

In `my_cond_branch_predictor.h`, the global predictor object was declared as `static`:
```cpp
static SampleCondPredictor cond_predictor_impl;
```
Because of the `static` keyword in a header file, every single translation unit (`.cc` file) that included this header ended up with its own independent, isolated copy of the `SampleCondPredictor` object. 

During execution:
- `cond_branch_predictor_interface.cc` would call `cond_predictor_impl.notify_instr_execute_resolve()`, populating its own copy's Tomasulo table.
- `my_cond_branch_predictor.cc` would invoke `sr_predict_wrapper()`, which called `cond_predictor_impl.sr_predict()` on a *completely empty* unupdated predictor instance.

Consequently, `sr_predict` never observed any valid registers. `num_available` for the banks was permanently 0, meaning the usefulness tables (UT) and weight tables (WT) were never updated, locking the computed `sR` multiplier safely at 0.0 for every single instruction in the simulation. This perfectly accounts for the G5 gate output stating `+0.0000 relative` movement.

### Fix
I modified the header to properly declare the global variable as `extern`:
```cpp
extern SampleCondPredictor cond_predictor_impl;
```
And then correctly instantiated it once inside `my_cond_branch_predictor.cc`:
```cpp
SampleCondPredictor cond_predictor_impl;
```
